## What the widget shows

Each widget shows **Today** (big) plus **one comparison period** that Eric picks per widget (Parameter, see §3), or — on the medium size only — a table of every period.

| Period | Parameter | Header label | Meaning (all America/Los_Angeles, up to now) |
|---|---|---|---|
| `today` | — | Today | since midnight |
| `d7` | `7d` (default / empty) | 7 days | today + the 6 days before |
| `d30` | `30d` | 30 days | today + the 29 days before |
| `qtd` | `qtd` | This quarter | since Jan 1 / Apr 1 / Jul 1 / Oct 1 (calendar quarter) |
| `ytd` | `ytd` | Year to date | since Jan 1 |
| (all) | `all` | table: Today · 7d · 30d · QTD · YTD | medium only; on small it falls back to 7d |

Default metrics:

| id | Label | Source | Meaning |
|---|---|---|---|
| `visits` | Visits | Cloudflare Web Analytics | Arrivals at the site (`sum{visits}`: page loads whose referrer is another site or none). Bots excluded. |
| `orders` | Orders | `Invoices` tab | Website orders (Note starts "Website order —"), Status not "Cancelled", by Timestamp. One invoice # = one order. |
| `revenue` | Sales | `Invoices` tab | Sum of **Grand Total** (tax included) of those same orders. Delete the line if Eric doesn't want $ on the home screen. |

Endpoint shape (per metric): `{ id, label, unit, periods: { today, d7, d30, qtd, ytd }, since? }` plus a top-level `periods: { d30: { label: "30 days", from: "2026-09-26" }, … }`. `today`/`week` are still included for older copies of the widget.

Ready-made extras (uncomment one line each in `IENN_METRICS`): `pageviews` (Cloudflare `count`), `plants` (units on website orders), `allorders` (every invoice incl. in-person ones from the invoice tool).
A brand-new kind of number = one line in `IENN_METRICS` plus, if the source doesn't compute it yet, one field in that source function.

Privacy: the endpoint returns **only labels, counts and totals** — no names, emails, phones, addresses, notes or invoice numbers (asserted in `tests/metrics.test.js`). It is read-only (never writes to any sheet), needs a secret key, and has no JSONP callback.

Caching: the whole payload (all periods) is cached in Apps Script for 10 minutes (2 minutes after a Cloudflare/sheet error), so many widgets with different Parameters share one fetch. Cloudflare's dataset limits are cached 6 hours. `&fresh=1` bypasses the payload cache. A refresh is 1 sheet read + 2 small Cloudflare requests (the limits read only every 6 h). The widget asks iOS to refresh every ~15 minutes (iOS decides the actual timing).

### The query (for reference)

`POST https://api.cloudflare.com/client/v4/graphql`, `Authorization: Bearer <token>`:

```graphql
{ viewer { accounts(filter: { accountTag: "a85e045b95745b2eea831457317a5f54" }) {
  settings { rumPageloadEventsAdaptiveGroups { maxDuration notOlderThan } }          # read once, cached 6 h
  s0: rumPageloadEventsAdaptiveGroups(limit: 1, filter: { AND: [
        { siteTag: "00379ec8474248f69ace426cd21d2126" }, { bot: 0 },
        { datetime_geq: "<piece start, UTC>", datetime_lt: "<piece end, UTC>" } ] }) { count sum { visits } }
  s1: …one alias per piece (see below), up to 8 per request…
} } }
```

`count` = page views, `sum.visits` = visits — the same two numbers the Web Analytics dashboard shows.

### Cloudflare range limits & retention (QTD / YTD)

- Each dataset has two account-specific limits, readable from the GraphQL **`settings`** node: `maxDuration` (widest time range one query may ask for) and `notOlderThan` (how far back data can be read), both in seconds. Cloudflare's docs say to read these rather than assume a plan value.
- Reported free-plan values for `rumPageloadEventsAdaptiveGroups`: **maxDuration 8 035 200 s = 93 days** (wider requests fail with "cannot request a time range wider than 13w2d") and **notOlderThan 15 897 600 s = 184 days**. Cloudflare keeps raw beacons 7 days, then a ~10 % sample (the API scales it back up; tiny sites are sampled less). The dashboard itself only shows 30 days.
- What the code does: it reads `settings` live (cached 6 h); if that read fails it uses a deliberately safe 30-day chunk / 31-day reach-back. It cuts the span from the earliest period start to now at every period start (today, 7d, 30d, quarter, Jan 1) and again so no piece is wider than `maxDuration`, queries those pieces as aliases (≤ 8 per request) and sums them — so each period is an exact sum of whole pieces. YTD in late December is ~5 pieces.
- **Beyond retention:** anything older than `notOlderThan` can't be read. The endpoint counts what is available and adds `since: { ytd: "2026-04-24" }` to the Visits metric; the widget marks that number with `*` and the footer says `*from Apr 24`. With 184 days this only affects **YTD from about early July onward**; QTD (≤ 92 days) and 30 days are never clipped. Orders/Sales come from the sheet and are never clipped.
- Practical note: the analytics beacon went live 2026-10-25, so all visit periods only start from then anyway (numbers just begin at 0, nothing breaks). Keeping a full-year visits history past 184 days would need a small nightly export into a sheet — not part of this draft.
- `iennMetricsCheckCloudflare()` logs the account's actual `maxDuration` / `notOlderThan` along with the siteTag check.

### Optional good/bad colours

Off by default (all numbers neutral sage). To turn on, edit `THRESHOLDS` near the top — per metric, per period (`today`, `d7`, `d30`, `qtd`, `ytd`):

```js
const THRESHOLDS = {
  visits: { today: { good: 20, bad: 3 }, d7: { good: 150, bad: 30 }, d30: { good: 600 } },
  orders: { d7: { good: 5, bad: 0 }, ytd: { good: 200 } },
};
```

`value >= good` → green, `value <= bad` → red, anything else neutral. Leave out `good` or `bad` to use only one; a period with no entry stays neutral. (The older `week` key still works for 7 days.) See `docs/screenshots/widget/medium-thresholds.png`.

### What the widget does when things go wrong

| Situation | Shows |
|---|---|
| No signal | Last saved numbers + red "Offline · Updated 7:42 PM" |
| Never loaded + offline | "No connection yet — will retry." |
| Wrong key | "Key not accepted" (+ last saved numbers if any) |
| Endpoint not deployed yet | "Server not ready" |
| Cloudflare down, sheet fine | Orders/Sales shown, Visits "–", "some data missing" |
| Period older than Cloudflare keeps | Visits number with `*`, footer "*from Apr 24" |
| Unknown Parameter | Falls back to 7d |
| ENDPOINT/KEY not pasted | "Open the script and paste ENDPOINT and KEY at the top." |
