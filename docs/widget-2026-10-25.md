## What the widget shows

For each metric: **today** (since midnight Pacific) and **last 7 days** (today + the 6 days before, Pacific), plus "Updated h:mm".
Default metrics:

| id | Label | Source | Meaning |
|---|---|---|---|
| `visits` | Visits | Cloudflare Web Analytics | Arrivals at the site (`sum{visits}`: page loads whose referrer is another site or none). Bots excluded. |
| `orders` | Orders | `Invoices` tab | Website orders (Note starts "Website order —"), Status not "Cancelled", by Timestamp. One invoice # = one order. |
| `revenue` | Sales | `Invoices` tab | Sum of **Grand Total** (tax included) of those same orders. Delete the line if Eric doesn't want $ on the home screen. |

Ready-made extras (uncomment one line each in `IENN_METRICS`): `pageviews` (Cloudflare `count`), `plants` (units on website orders), `allorders` (every invoice incl. in-person ones from the invoice tool).
A brand-new kind of number = one line in `IENN_METRICS` plus, if the source doesn't compute it yet, one field in that source function.

Privacy: the endpoint returns **only labels, counts and totals** — no names, emails, phones, addresses, notes or invoice numbers (asserted in `tests/metrics.test.js`). It is read-only (never writes to any sheet), needs a secret key, and has no JSONP callback.

Caching: results are cached in Apps Script for 10 minutes (2 minutes after a Cloudflare/sheet error). `&fresh=1` bypasses it. The widget asks iOS to refresh every ~15 minutes (iOS decides the actual timing).

### The query (for reference)

`POST https://api.cloudflare.com/client/v4/graphql`, `Authorization: Bearer <token>`:

```graphql
{ viewer { accounts(filter: { accountTag: "a85e045b95745b2eea831457317a5f54" }) {
  t: rumPageloadEventsAdaptiveGroups(limit: 1, filter: { AND: [
       { siteTag: "00379ec8474248f69ace426cd21d2126" }, { bot: 0 },
       { datetime_geq: "<today 00:00 Pacific, as UTC>", datetime_lt: "<now>" } ] }) { count sum { visits } }
  k: rumPageloadEventsAdaptiveGroups(limit: 1, filter: { AND: [ …same…, { datetime_geq: "<6 days ago 00:00 Pacific>", datetime_lt: "<now>" } ] }) { count sum { visits } }
} } }
```

`count` = page views, `sum.visits` = visits — the same two numbers the Web Analytics dashboard shows.
**siteTag vs token:** the dataset is filtered by `siteTag`. Cloudflare's site list (`/rum/site_info/list`) returns `site_tag` and `site_token` as separate fields; for most sites the beacon `token` is the value used as `siteTag`, so the draft defaults to `00379ec8474248f69ace426cd21d2126`. This can't be confirmed without a token, so `iennMetricsCheckCloudflare()` (read-only) lists every `siteTag` + hostname with data in the last 7 days; if IENN's tag differs, set `CF_SITE_TAG`. Errors come back as HTTP 200 with an `errors` array — the code checks both.

### Optional good/bad colours

Off by default (all numbers neutral sage). To turn on, edit `THRESHOLDS` near the top:

```js
const THRESHOLDS = {
  visits: { today: { good: 20, bad: 3 }, week: { good: 150, bad: 30 } },
  orders: { week:  { good: 5,  bad: 0 } },
};
```

`value >= good` → green, `value <= bad` → red, anything else neutral. Leave out `good` or `bad` to use only one. See `docs/screenshots/widget/medium-thresholds.png`.

### What the widget does when things go wrong

| Situation | Shows |
|---|---|
| No signal | Last saved numbers + red "Offline · Updated 7:42 PM" |
| Never loaded + offline | "No connection yet — will retry." |
| Wrong key | "Key not accepted" (+ last saved numbers if any) |
| Endpoint not deployed yet | "Server not ready" |
| Cloudflare down, sheet fine | Orders/Sales shown, Visits "–", "some data missing" |
| ENDPOINT/KEY not pasted | "Open the script and paste ENDPOINT and KEY at the top." |
